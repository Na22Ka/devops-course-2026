# Сравнение Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто **указатель на коммит** (файл размером ~41 байт).
Создание ветки не копирует файлы, а лишь создаёт ссылку на уже существующий
снимок. Поэтому операция мгновенная и не требует сети.

В SVN ветка — это **физическая копия директории** внутри репозитория
(`/branches/feature-x/`). Она хранит полную структуру файлов, поэтому
создание ветки требует копирования данных **на сервере** и может занимать
минуты на больших проектах.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

**Нет.** SVN — централизованная система: коммит всегда отправляется на
центральный сервер, и без сети операция невозможна. Локально можно только
править файлы и смотреть diff, но зафиксировать изменения — нет.

В Git коммит делается локально (в свою полную копию репозитория) и не
требует сети. Push нужен только для отправки на удалённый сервер.

## 3. В каких сценариях SVN может быть предпочтительнее Git?

- **Legacy-проекты** в госсекторе и банках, где SVN уже развёрнут
  и миграция дороже поддержки.
- **Проекты с большими бинарными файлами** (дизайн, медиа), где полная
  копия репозитория у каждого разработчика нецелесообразна.
- **Жёсткий контроль доступа** к частям репозитория — в SVN проще
  разграничить права по директориям.
- **Команды с линейной историей** без активного ветвления, где все плюсы
  Git не востребованы.
- **Требование централизованного аудита** — все коммиты сразу на сервере.
